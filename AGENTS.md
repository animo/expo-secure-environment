## What this is

`@animo-id/expo-secure-environment` is an Expo module that creates P-256 keys in the device's secure hardware and signs with them: the Secure Enclave on iOS, StrongBox, the TEE or the software keystore on Android. Signing can require biometrics or the device passcode, and Android keys can have a key attestation.

## Layout

- `src/`: the TypeScript API (`index.ts`), its types and the error classes.
- `ios/` (Swift) and `android/` (Kotlin): the native module.
- `example/`: an Expo app in the pnpm workspace. `App.tsx` is a screen to try everything by hand, `example/tests/*.harness.ts` are the automated tests. `example/ios` and `example/android` are generated by `expo prebuild` and not committed.

Native errors reach JavaScript by code, derived from the exception class name (`KeyNotFoundException` becomes `ERR_KEY_NOT_FOUND`). A new error needs a class in `ios/error.swift`, in `android/.../SecureEnvironmentExceptions.kt` and in `src/SecureEnvironmentError.ts`, with the code in its map.

## Checks

Run from the repo root after every change, and fix what they find:

- `pnpm style:fix`: Biome 1.x formatting and lint.
- `pnpm types:check` and `pnpm build`.
- `npx tsc --noEmit` in `example/`, which type checks the example and the tests.

## Tests

The tests use [React Native Harness](https://react-native-harness.dev): Jest-style tests that run inside the example app on a device. Use the `react-native-harness` skill (`.claude/skills/react-native-harness/SKILL.md`) to write or debug them.

From the repo root:

- `pnpm test:android` and `pnpm test:ios`: an emulator and a simulator. Harness creates or boots the device and installs the app.
- `pnpm test:android:device` and `pnpm test:ios:device`: the phone connected with a cable (USB debugging on Android; unlocked and trusting the Mac on iOS). The script finds the device and builds and installs the app on it. iOS signs with your Apple development certificate, and asks which one when there are several.

Each script builds the app first (`example/harness/run.mjs`), so native changes are included. Jest arguments go at the end, e.g. `pnpm test:android -t "keys"`.

On physical devices the tests require secure hardware: the TEE (and StrongBox where the device has it) or the Secure Enclave. Emulators store keys in software, so there the key tests accept that. Emulators and simulators have no enrolled biometrics. Tests that show a biometric or passcode prompt can't run unattended; test those by hand with `App.tsx`. CI runs the emulator and simulator tests (`.github/workflows/ci.yaml`).

## Dependencies

- Use pnpm 12, the version CI uses. pnpm 10 can't use the store this lockfile was installed with.
- Versions the library and the example share are in the `catalog:` in `pnpm-workspace.yaml`, so Metro bundles a single copy of react and react-native. Bump them there.
- pnpm only runs install scripts of packages listed in `allowBuilds` in `pnpm-workspace.yaml`, and fails the install for packages with scripts that aren't listed.
- Expo SDK 56 (React Native 0.85.3). SDK 57 doesn't build with Xcode 26.2.

## Commits and releases

Commits use Conventional Commits, e.g. `fix: pad r and s to 32 bytes in raw signature conversion`.

There are no changesets. A release runs from the `Pipeline` workflow (`ci.yaml`) with `workflow_dispatch` on `main` and a release type, and publishes to npm with release-it. Only release when asked.
